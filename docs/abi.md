# myos 用户态 ABI

这份文档是**内核与用户程序之间的合同**。`kernel32/syscall.cpp` 和 `user/` 下的程序是它的
两份实现，`docs/design.md` 讲的是为什么这样写。一旦有程序按它编译过，改这里就等于改 ABI：
调用号只增不改，结构体只加不改。

## 1. 怎么发起一次调用

```
eax = 调用号
ebx = 第 1 个参数
ecx = 第 2 个参数
edx = 第 3 个参数
esi = 第 4 个参数（目前没有调用用到）
edi = 第 5 个参数（目前没有调用用到）
int 0x80            ; DPL 3 的中断门，见 kernel32/idt.cpp
返回值在 eax         ; 负数表示错误
```

- `ebx/ecx/edx` 只当作参数用；`int 0x80` 由内核保存/恢复**所有**寄存器，所以调用前后
  除了 `eax` 之外没有寄存器会被改动（`user/hello.cpp` 里就是按这个写的）。
- 内核在内核态执行期间把 `ds/es/fs/gs` 换成内核选择子，返回用户态前恢复成用户的，
  所以程序不需要自己管段寄存器。
- 目前没有 `sysenter`/`syscall` 快路径，也没有 vDSO：`int 0x80` 足够，而且它不需要
  额外的 MSR 初始化。

## 2. 调用表（v1）

| 号 | 名字 | 参数 | 返回 | 状态 |
|---|---|---|---|---|
| 1 | `exit` | `ebx` = 退出码 | 不返回 | 已实现 |
| 4 | `write` | `ebx` = fd，`ecx` = 用户缓冲区，`edx` = 字节数 | 写入的字节数，或负错误码 | 已实现，只支持 fd 1/2（控制台） |
| 20 | `getpid` | — | 1 | 已实现（占位：现在系统里只有一个任务） |
| 158 | `yield` | — | 0 | 已实现（占位：还没有调度器，直接返回） |

调用号沿用 Linux i386 的编号（`exit`=1、`write`=4、`getpid`=20、`sched_yield`=158），
这样以后写用户态 libc 时不用再翻译一遍。未实现的号返回 `E_NO_SYS`。

**还没有的**：`open/close/read/lseek/stat`、`fork/exec/wait`、`pipe`、`brk/mmap`、
`kill/sigaction`、时间相关的调用。它们按路线图在第二、三、五阶段加入，调用号先空着。

## 3. 错误码

负数，分两个区，**不重叠**：

| 区 | 谁在用 | 值 |
|---|---|---|
| -1..-16 | 文件系统（`kernel32/fs.h` 的 `FsError`） | `FS_NO_ENT` = -5 等 |
| -32..-39 | 系统调用（`kernel32/usercopy.h`） | 见下表 |

| 值 | 名字 | 含义 |
|---|---|---|
| -32 | `E_PERM` | 不允许 |
| -33 | `E_NO_ENT` | 文件或目录不存在 |
| -34 | `E_BAD_F` | 文件描述符无效 |
| -35 | `E_AGAIN` | 会阻塞（还没有阻塞语义） |
| -36 | `E_NO_MEM` | 内存不足 |
| -37 | `E_FAULT` | 用户指针不可用（越界、未映射、或指向内核） |
| -38 | `E_INVAL` | 参数无效（包含"这个文件不是用户程序"） |
| -39 | `E_NO_SYS` | 没有这个系统调用 |

两个区必须分开，因为值撞车就是含义撞车：第一版里 `E_FAULT` 和 `FS_BAD_FD` 都是 `-14`，
而打印"哪里错了"的函数只能有一个意思。`sys_error_text()` 两个区都能翻译。

## 4. 用户地址空间（v1）

| 范围 | 用途 |
|---|---|
| `0x40000000` 起 | 程序镜像（代码/只读数据/数据/bss 都在里面，由内核按页映射） |
| `0x40100000` 起，16 KiB | 栈，`esp` 初值 = 栈顶（向下增长） |
| `0x40000000`..`0x50000000` | **用户窗口**：只有这段里的地址会被 `copy_from_user/copy_to_user` 接受 |
| 其它 | 内核的，用户态访问会触发缺页并被当作故障报告 |

映射规则：用户页是 present + writable + user；内核页是 present + writable，**没有 user 位**，
而且页目录项也不带 user 位（两级都必须允许才行——只给页表项加 user 位的话，Ring 3 访问
会报一个"present + user"的缺页，看起来像页的问题，其实是目录项拒绝的）。

地址空间是**每个程序一份、用完就收**：`run` 结束时镜像页和栈页都会解映射并归还物理页，
所以连续 `run` 两次和跑一次在分配器看来是一样的。现在没有多任务，所以也就没有"地址空间
属于谁"的问题；第二阶段会有。

## 5. 用户程序镜像格式

和内核镜像同一个 16 字节自校验头，架构字节是 3：

```
0  "MYOS"   4 架构 = 3   5 版本   6 flags   7 校验和（16 字节和为零）
8  入口偏移(dword)                 12 总大小(dword)
```

内核在映射任何一页之前先校验它（`kernel32/user.cpp::user_image_ok`）：magic、架构必须是 3、
16 字节和为 0、`size` ≤ 256 KiB、`16 ≤ entry < size`。任何一条不过就返回 `E_INVAL`，
一个字节都不会被映射。

程序由构建系统产出：`user/header.asm`（那个头）+ 程序源码，用 `-m32 -ffreestanding` 编译、
用项目自带的 `tools/cofllink.py` 按 `user_layout()` 链接到 `0x40000000`，入口符号是
`user_entry`（不是 `main`：这里没有 C 运行时，也没有人来 `call` 它）。产物打进 myfs 卷的
`/bin/` 下，和别的文件一样受 manifest 校验和检查。

## 6. 现在能保证什么、不能保证什么

**保证**：Ring 3 看不到内核内存（内核页不带 user 位）；所有系统调用的指针参数都过
`user_range_ok()`（逐页检查 present + user）；`write` 会先把用户缓冲区拷进内核缓冲区再输出，
所以驱动程序拿到的是稳定的内存；程序退出后它的地址空间就没映射了。

**不保证**：没有地址空间隔离之外的隔离（没有 uid/权限）；程序可以用完 256 KiB 的用户窗口
里所有它要得到的页（没有配额）；`write` 现在是逐个 256 字节块走的，不是一次拷贝；没有
`fork`，所以也没有"父子的地址空间"这个概念。
