## 术语表

| 词 | 一句话解释 |
|---|---|
| **实模式 / 保护模式** | 8086 时代的 16 位运行方式（1 MiB 寻址、没有内存保护）／现代 32 位方式（段基址加偏移、有权限） |
| **LBA / CHS** | 磁盘寻址的两种说法：LBA 是"第几个扇区"，CHS 是"第几柱面、磁头、扇区"。BIOS 的 `INT 13h` 只会 CHS，所以 loader 要换算 |
| **MBR / VBR** | 磁盘第 0 扇区的分区表（MBR）；分区自己的第一个扇区（VBR）。BIOS 先跑 MBR，再把控制权交给活动分区的 VBR |
| **扇区** | 磁盘的最小读写单位，这里是 512 字节 |
| **GDT / IDT** | CPU 用的两张表：GDT 描述内存段（这里只有"整块 4 GiB"的平坦段），IDT 描述中断处理函数 |
| **PIC / PIT / IRQ** | 老式中断控制器（把硬件中断重编号送 CPU）／可编程定时器（这里 100 Hz）／硬件中断线（键盘 1、串口 4） |
| **A20** | 一条历史遗留的地址线，不开就只能看到 1 MiB 内存 |
| **EBDA / E820** | BIOS 数据区之上的扩展数据区（约 0x80000 起）／固件报告内存分布的调用号 |
| **超级块 / inode / 位图 / 目录项** | 卷的控制块（格式版本、容量、空闲计数）／"一个文件或目录"的记录（类型、大小、块号）／记录哪些块和数据块被占用的位表／目录里"名字 → inode 号"的 32 字节记录 |
| **直接块 / 间接块** | inode 里直接写块号的 11 个位置；不够时再用一个"块号数组"块（指针表）装 256 个 |
| **写穿** | 写下去就落盘，不攒在内存里；代价是慢，好处是断电只丢"最后一次操作没做完的部分" |
| **fsck** | 一致性检查/修复：回收"被标成占用但没人引用"的块、修正计数、清脏标记 |
| **manifest** | 构建时生成的文件清单（名字 尺寸 校验和），内核每次启动逐文件重算比对 |
| **DMA / PIO** | 外设直接搬内存／CPU 一个个字节搬。软驱读盘走 DMA，所以有 64 KiB 边界限制；本项目自己的硬盘驱动用轮询 PIO |
| **扫描码** | 键盘发的不是字符而是"哪个键"的编号，要查表加 shift 状态才变成字符 |
| **任务 / 上下文切换** | "一个正在跑的执行体"（这里 = pid + 状态 + 一块内核栈 + 一份页目录）；切换 = 保住当前这几个寄存器、把栈换成另一个任务的，等它以后被换回来时从那一点继续 |
| **轮转 / 时间片 / 抢占** | 让每个可运行任务轮流跑一段固定时间（这里 2 个 tick = 20 ms）；"抢占"= 时间到了由定时器**强行**换人，而不是等任务自己让出 |
| **CR3 / esp0** | CPU 里指向当前页目录的寄存器／TSS 里"从 ring 3 掉进内核时用哪条栈"的字段——这两个是必须跟着任务走的东西 |
| **僵尸 / 回收** | 已经退出、但退出码还没被创建者取走的任务（槽位还留着）／把它的栈还给堆 |
| **里程碑 A/B/C/D/E/F** | 本项目自己的进度划分：A = 进保护模式并跑起来，B = 中断/驱动/shell，C = 磁盘与文件系统，D = 分页/物理分配/堆/缺页，E = ring3 + syscall，F = 任务与调度 |

## 总体结构与引导链

```
BIOS
 └─ LBA 0 的引导扇区 (boot/boot16.asm, 正好 512 字节)
     ├─ 打印 "myos boot"
     ├─ INT 13h 读 LBA 1..8 → 0x0000:0700
     └─ 远跳转到 0000:0700（跳转字节由 build.py 校验，见踩坑记录）
         └─ stage2 (boot/stage2.asm)
             ├─ 画横幅、探测磁盘几何
             ├─ 先读 1 个扇区到暂存区，校验内核镜像头
             └─ 按架构字节分两条路：
                 ├─ arch=1: 整个镜像读到 0x8000，远跳转进 16 位内核
                 └─ arch=2: 整个镜像读到 0x10000（暂存）→ 采集 E820 → 开 A20
                            → 装 flat GDT → CR0.PE → 32 位入口把镜像搬到 0x100000
```

两个内核共用同一个 loader、同一套镜像格式和同一个构建脚本。

```
boot/boot16.asm   512 字节引导扇区：报告、读 stage2（8 扇区）、远跳转
boot/stage2.asm   画横幅、探测几何、校验头部、加载内核；32 位还要开 A20 进保护模式
boot/boot.inc     唯一的常量来源（地址、预算、颜色、端口），build.py 与它有测试交叉校验
kernel16/*.asm    16 位内核：直写显存的文本控制台 + 键盘 + 命令行 shell
kernel32/*.asm    32 位内核的汇编部分：镜像头、入口桩（切栈）、ISR 桩、调试退出
kernel32/*.cpp    32 位 C++ 内核：控制台、GDT/IDT/PIC/PIT、键盘、ATA、myfs、shell、自检
kernel32/pmm.*    物理页分配器（按 E820 的位图）；paging.* 二级页表 + 缺页恢复；
                  heap.* 内核堆（首次适配 + 合并）；panic.* 统一的停机报告
tools/cofllink.py 自研 COFF/PE32 链接器（这台机器上没有能产裸机镜像的 ld）
tools/myfs.py     myfs 的主机侧实现：打包、读取、校验、造故障镜像
tools/qemu.py     QEMU 后端：TCP 串口抓取 transcript、monitor 按键、退出码
emulator/*.py     自研 16 位 x86 模拟器 + BIOS + VGA 文本渲染
run.py            跑镜像：按镜像头里的架构字节自动选后端
memmap.py         打印常量/内核布局/内存层配置/磁盘布局/运行时内存快照
```

## 内核镜像头

两个架构共用同一个 16 字节自校验头，位于镜像偏移 0：

```
0  "MYOS"   4  架构(1=16位 2=32位)   5  版本   6  flags   7  校验和
8  入口偏移(dword)                    12 总大小(dword)
```

`build.py` 回填入口偏移、大小和校验和——这三者在汇编里写不出来，因为
`kernel_main - image_header` 是跨段差值，属于 16 位重定位。loader 在跳转前校验 magic、
架构和"16 个字节和为零"，所以损坏的镜像会被**报告**而不是被执行。

入口和大小是 dword：32 位镜像必然超过 64 KiB，word 装不下，校验和因此从偏移 12 挪到
偏移 7（原来那里是 size 的低字节）。

## 内存布局

由 `boot/boot.inc` 单点定义：

| 地址 | 用途 |
|---|---|
| `0x0000:0500` | BIOS 数据区 |
| `0x0000:0700` | stage2（最多 8 × 512 = 4 KiB） |
| `0x0000:3000` | 暂存区：内核首扇区（校验头用） |
| `0x0000:6000` | 引导信息块（进保护模式前由 loader 写好） |
| `0x0000:7B00` | 加载器运行时的栈顶，也是交接用的栈顶 |
| `0x0000:7C00` | 引导扇区：BIOS 把它放这里，它就留在这里 |
| `0x0000:8000` | 16 位内核镜像（最多 24 KiB） |
| `0x0000:A000` | 16 位内核栈顶（向下增长） |
| `0x00010000`–`0x00080000` | 32 位镜像的暂存窗口（448 KiB，到 EBDA 为止） |
| `0x00100000` | 32 位内核运行地址（需要 A20） |
| `0x00200000` | loader 进入 32 位内核前的引导栈 |
| `0x000B8000` | VGA 文本缓冲区 |

32 位内核的栈在它自己的 `.bss` 里（16 KiB），而且是 `.bss` 的**最后**一段——栈向下
增长，放在最后意味着静态变量在栈底之下，普通函数调用不会覆盖它们。

`0x80000` 是扩展 BIOS 数据区（EBDA）起点，所以暂存窗口到此为止。`python memmap.py`
打印的就是这些数字（从源码和产物里量出来，不是抄文档）。

## 磁盘布局

软盘（1.44 MiB）和硬盘镜像共用前 1024 个扇区：

| LBA | 内容 |
|---|---|
| 0 | 引导扇区（同时也是硬盘镜像的 MBR） |
| 1..8 | stage2（8 扇区预算） |
| 128..1023 | 内核镜像（896 扇区 = 448 KiB 预算） |

内核故意放在 LBA 128：loader 把 16 位内核读到物理 0x8000，也就是 LBA 64；如果内核紧挨着
stage2 放在 LBA 9，读盘会覆盖加载器自己的代码。

**32 位的硬盘镜像还要大一些（2 MiB）**，多出来的部分是文件系统：

| LBA | 内容 |
|---|---|
| 2048..4095 | myfs 卷（分区 1，类型 `0x7F`，2048 块 × 512 B = 1 MiB） |
| 4096..4103 | 设备测试区（scratch），只有 `blk test` 会碰 |

引导容器（分区 0）被缩短到 LBA 1..2047，**不再和卷重叠**：内核是遍历分区表、按类型字节
找卷的，而不是靠写死的 LBA——所以同一份卷放在引导盘上还是放在用户的数据盘上，内核的
代码完全一样。`python memmap.py --arch 32 --image` 打印这张表。

## 里程碑 A：32 位内核能跑起来

`boot/stage2.asm` 读到架构字节是 2 时走另一条路：

1. 把整个镜像读进 **0x10000 的暂存窗口**。读盘用线性目标地址、每块重新算 `ES:BX`——
   固定段的话偏移会在 64 KiB 处回绕，把镜像写到自己身上，看起来却像内核损坏。
2. 在实模式下用 `INT 15h E820` 采集内存图，连同启动盘号、VGA 模式写进**引导信息块**
   （0x6000，布局见 `kernel32/bootinfo.h`，地址与 `boot.inc` 有测试交叉校验）。
3. 打开 **A20**（BIOS 服务 → 0x92 fast A20），然后**验证**：往线性 0x5000 和 0x105000
   写不同值再比对，禁止"报告成功但没打开"。
4. `lgdt` 装 flat GDT（code 0x08 / data 0x10，base 0、limit 4 GiB），置 `CR0.PE`，
   用**手工编码的** `66 EA` 远跳进入 32 位（和引导扇区同一个理由：nasm 的
   `jmp seg:label` 从文件头算偏移，`build.py` 会校验这段字节）。
5. 32 位入口把暂存镜像 `rep movsb` 搬到 **0x100000**，从镜像头里读入口偏移跳过去。

内核自检里有一条"暂存副本 vs 已加载副本"的前 272 字节比较，证明拷贝步骤；**整份镜像**
的校验和则打印出来交给宿主比对（见踩坑记录里那条 64 KiB 边界的 bug）。

## 里程碑 B：中断、驱动与 shell

| 组件 | 说明 |
|---|---|
| `gdt.cpp` | 内核自己的 flat GDT（null/code32/data32），`lgdt` + 重载所有段寄存器（CS 靠 `retf` 假远跳）。自检用 `sgdt` 读回 CPU 里的实际值来验证 |
| `idt.cpp` + `isr.asm` | 256 项 IDT；0–31 异常、32–47 IRQ 各有汇编桩，共用一个保存现场 → 调 C++ → `iret` 的公共路径。异常会打印向量名/EIP/错误码后停机，**不再是三重故障** |
| `pic.cpp` | 8259 重映射到 0x20/0x28，只放行 IRQ0（定时）、IRQ1（键盘）、IRQ4（串口）；EOI 由派发器统一发送，驱动不可能忘记 |
| `pit.cpp` | PIT 通道 0，100 Hz，`pit_ticks()` 是内核唯一的时间概念；自检用"ticks 会不会涨"验证整条中断链 |
| `keyboard.cpp` | IRQ1 读 0x60，set-1 扫描码解码（shift/caps/退格/回车），进统一按键队列 |
| `console.cpp` | COM1 既输出也输入：IRQ4 里**循环抽干 FIFO**，触发等级设成 1 字节 |
| `shell.cpp` | 命令表 + 行编辑（回显、退格、拒绝超长）、第一个词大小写不敏感匹配 |
| `mem.cpp` | 用引导信息里的 E820 图回答 `mem` |

输入只有一条队列：键盘（IRQ1）和串口（IRQ4）都往里推字符，所以"人在 QEMU 窗口里打字"
和"测试从串口喂一行"走的是同一套代码——这也是这个阶段能被自动验收的原因。

## 里程碑 C：ATA 驱动、MBR 与 myfs

### 内核自己驱动硬盘

`ata.cpp` 走主 IDE 通道（0x1F0，LBA28，**轮询 PIO**：不用中断、不用 DMA、不扫 PCI）。
所有等待都有上界，设备不回答就报 I/O 错误并计数（`blk` 会打印超时次数），而不是让内核
挂在状态位上。`identify` 之后还要看 LBA mid/high 寄存器，避免把 ATAPI/SATA 设备当成
普通 ATA 盘；通道状态读到 `0x00` 或 `0xFF` 都算"没有盘"。

### myfs 格式

块 512 字节，小端：

| 位置 | 内容 |
|---|---|
| 块 0 | 超级块：magic/版本/块大小/块数/inode 数/首个数据块/空闲计数/卷标/状态位 |
| 块 1..4 | inode 表，64 个 inode × 32 字节 |
| 块 5 | 位图：inode 位图 8 字节 + 块位图 256 字节 |
| 块 6.. | 数据块 |

inode 32 字节：类型、填充、大小、12 个 2 字节块号——11 个直接块 + 1 个一级间接块（256 个
块号），所以单文件上限 (11+256)×512 = 136704 字节。目录是"数据块里放 32 字节目录项"的
inode（29 字符 NUL 结尾名 + 2 字节 inode 号，每块 16 项）。`.` 由路径解析直接跳过，`..`
明确返回"不支持"——不存父指针就不要猜。

### 两个实现，互相校验

`tools/myfs.py`（Python）与 `kernel32/fs.cpp`（C++）是同一份格式的两份实现。构建时额外
写入 `/manifest`（每行 `路径 尺寸 校验和`），内核每次启动**逐文件重算校验和比对**，所以
"两端理解一致"不是假设，而是每条启动都验一遍的事实。`tests/test_myfs.py` 还会把 Python
常量与 `kernel32/fs.h` 的常量逐一求值比对（含
`FS_ENTRIES_PER_BLOCK = FS_BLOCK_SIZE / FS_DIRENT_SIZE` 这种表达式）。

反方向也验：内核写下去的文件，测试用 `tools/myfs.py` 在宿主机上读出来。

### 写路径：为什么是这个顺序

写穿——数据块写下去就到盘上，元数据在每次操作结束前落盘：

| 操作 | 顺序 |
|---|---|
| 分配/创建 | 位图（标为已用，**立刻落盘**）→ 数据 → inode → 超级块计数 |
| 删除/收缩 | 目录项 → inode 指针清空 → 位图（标为空闲）→ 超级块计数 |

规则只有一句：**绝不允许"盘上的 inode 指向一个盘上还标着空闲的块"**。上表两个方向都
满足它，代价是崩溃可能留下"标成占用但没人引用"的漏块——而这正是 `fsck` 能回收的东西。
反过来（先把块标空闲再清 inode）会留下一个"活着但指向已被分配出去的空间"的文件，那是
数据损坏。

第一次写入会把超级块状态位置成 dirty，`sync` 或 `reboot` 置回 clean；下次启动看到 dirty
会打印警告，`fsck` 负责检查并回收。间接块是**指针表**，新分配时必须先写 512 个零，否则
会把上一个文件留下的块号当成自己的。

### fsck 修什么、不修什么

修：漏块（回收）、"被引用却标记空闲"的块（标为已用）、空闲计数不符（重算）、
"位图说已用但 inode 表说空闲"（清掉位图位）、脏标记（清掉）。

不修：**孤儿 inode**（已分配但从根目录到不了）只报告不删除——删掉它等于替用户猜那是哪
个文件。`blk test` 是内核里唯一往盘上写测试数据的地方，写在所有分区之外，这样"写坏了"
只可能是驱动的问题。

## 里程碑 D：内存管理（路线图第一阶段 1a，已完成）

三层，启动顺序是硬件逼出来的：**分配器 → 分页 → 堆**。

| 文件 | 做什么 | 关键点 |
|---|---|---|
| `pmm.cpp` | 4 KiB 页的位图分配器，从 E820 的可用区间建表 | 只管理 1 MiB 以上的内存；低 1 MiB 是 IVT/BDA/显存/loader 暂存区，不碰；位图覆盖 128 MiB，超出的内存**计入 ignored 并报告**，不假装有 |
| `paging.cpp` | 二级页表（无 PAE），启动时建立 identity map 并打开分页 | 先映射再开 CR0.PG——顺序错了下一条指令就取不到；页目录/页表本身从 PMM 分配（见下方陷阱）；内核映射一律不带 PAGE_USER |
| `heap.cpp` | 1 MiB 连续竞技场上的首次适配 + 分割 + 相邻合并 | 竞技场一次 `pmm_alloc_pages()` 拿连续页；每块 16 字节头带 magic + 自校验和，越界写会在下一次分配时报出来而不是变成"分配到了别人的块" |
| `panic.cpp` | 统一的停机报告：原因、向量、EIP、错误码、寄存器 | 用 `isa-debug-exit` 写失败状态，所以测试能区分"内核说了哪里错了"和"内核消失了" |

**缺页处理**：14 号向量的处理器先问 `paging_handle_fault()`；能恢复就返回，让 `iret` 重试
那条指令（这就是"按需零页"：读一个从没碰过的地址，内核分配一页、清零、映射，然后读回 0）。
不能恢复就打印 CR2 + 错误码（present/write/user）并 panic。今天是"能满足的"和"不能的"两种，
将来的 COW/栈增长/mmio 都挂在同一个钩子上。

**开机就能看到的数字**（都是量出来的，不是写死的）：`vm` 命令打印 PMM 的 managed/free/used、
usable RAM 的结尾、CR3、页表数、已映射页数、已处理缺页次数、demand-zero 区间数、堆的
arena/free/largest/used/blocks/live/bad-free。`python memmap.py --memory` 打印**配置**
（页大小、PMM 上限、堆竞技场、按需区间上限），数字从 `pmm.h/paging.h/heap.h` 里解析出来。

**验收**（`Kernel32MemoryTests`/`Kernel32PageFaultTests`）：14 条内存自检（分配器来回、
identity map、映射/解映射、堆分配不互相破坏并归还、超请求被拒、按需零页缺页一次并把页
交给它）；`vm fault` 故意写未映射地址 → 串口出现 CR2/错误码/寄存器，进程以失败码退出，
QEMU 的 `-d int` 日志里是 `v=0e` 而**不是** triple fault。

## 里程碑 E：特权级与系统调用（路线图第一阶段 1b，已完成）

内核第一次拥有"用户态"：ring 3 的程序跑在自己的页上，只能通过 `int 0x80` 让内核替它做事。

| 文件 | 做什么 | 关键点 |
|---|---|---|
| `gdt.cpp` | GDT 从 3 项扩到 6 项：ring0 code/data、ring3 code/data（DPL 3）、TSS | 用户描述符和内核的只有权限位不同（0xFA/0xF2 对 0x9A/0x92）；选择子要带 RPL 3，拼错就是加载段寄存器时的 #GP |
| `tss.cpp` | TSS（104 字节），`ss0/esp0` 指向"当前用户上下文专属的"内核栈 | 没有它，ring3 的陷阱会把帧压到**用户自己的栈**上——内核在一块它要防的程序能写的内存上运行；`iomap_base` 指到结构末尾 = 没有 I/O 位图 |
| `ring3.asm` | `int 0x80` 桩；`run_user_image`（保存内核栈 + callee-saved 后 iret 进 ring3）；`return_to_kernel`（恢复栈和寄存器，把退出码放 `eax` 回到 C++） | 进 ring3 前必须把 ds/es/fs/gs 换成用户选择子；返回路径带着 IF=0 回来（它刚恢复栈，不能被 tick 打断），**之后必须由内核重新开中断** |
| `syscall.cpp` | 调用号分派；v1：`exit`/`write`/`getpid`/`yield`；`write` 先把用户缓冲区拷进内核缓冲区 | ABI 写在 [`docs/abi.md`](abi.md) |
| `usercopy.cpp` | `user_range_ok`（逐页查 present + user）、`copy_from_user/copy_to_user` | 只有用户窗口（0x40000000..0x50000000）里的地址会被接受；错误码用 -32..-39 的独立区间 |
| `user.cpp` | `exec_user(path)`：读镜像 → 校验头 → 映射页（先清零）→ 映射栈 → 进 ring3 → 收页 | 头部不过就**一页都不映射**；每次 run 用一段专属内核栈，跑完归还 |
| `panic.cpp` / `klog.cpp` | 统一停机报告；`dmesg` 能读的环形日志 | 每一次进出 ring 3 都进日志，所以"有没有真的切成用户态"是能查的 |

**用户镜像**：和内核同一个 16 字节自校验头，架构字节是 3。`tools/cofllink.py` 增加
`user_layout()`（没有内核那个 `.bss.stack`），`build.py` 的 `build_user()`/`build_users()` 按
`0x40000000` 链接、回填头部、校验，`stage_volume_tree()` 把 `files/` 和 `bin/<名字>` 合成一个
目录交给 `myfs.py` 打包——打包器本身仍然只管格式，不管源从哪来。

**验收**：15 条自检（描述符 DPL、TSS 已 `ltr`、门 DPL、用户页/内核页的权限位、用户指针
校验、镜像头校验）+ 两个 QEMU 测试类。最有力的一条是 `run /bin/badwrite`：它让内核去读
`0x00100000`（内核镜像）并打印 8 字节，退出码必须是 37（E_FAULT），而且串口里不能出现内核
镜像开头的 `MYOS`——退出码和字节泄漏两条一起看，才能证明"拒绝"和"没读到"是一回事。

## 里程碑 F：任务与调度（路线图第二阶段 2a，已完成）

内核第一次有"不止一个东西在跑"：一张任务表、一个由定时器抢占的轮转调度器，以及**在内核里**
上下文切换所需的那点汇编。2a 只做内核任务——用户程序还不是任务，`fork`/写时复制/信号/管道
是 2b/2c。

| 文件 | 做什么 | 关键点 |
|---|---|---|
| `task.cpp` | `Task` 表（16 槽）、`task_create_kernel`（建栈 + 建页目录 + 造栈帧）、`task_exit`、`task_join`、`task_reap` | 新任务的栈是"造"出来的：六个字，顶上那个是 `task_trampoline` 的地址，中间那个 EFLAGS 带 IF=1，于是新任务的生命从一次它没调用过的函数返回开始。状态机里有一个 `New`：**结构体填完之前它不能被调度** |
| `switch.asm` | `switch_to(save_esp, next_esp)`：压 ebp/ebx/esi/edi **和 EFLAGS**、存 esp、换 esp、`popfd` + 弹出、`ret` | 只有这一个函数必须用汇编；其余（谁下一个跑、什么时候、TSS/CR3 什么时候换）都在 C++ 里，因为那些写错了会**报错**而不是静默跑飞 |
| `sched.cpp` | 轮转（扫表，不用队列）、`schedule()`/`sched_yield()`/`sched_tick()`、`sched_pause/resume` | 切换顺序固定：**关中断 → 改状态 → TSS esp0/CR3 → 告诉任务层 → 换栈 →（被换回来时）恢复自己的 IF**。每一步都必须在"栈已经不是自己的"之前完成 |
| `paging.cpp`（改） | 多了一个"当前目录"的概念：`paging_active_directory()` / `paging_clone_directory()` / `paging_switch_directory()` | 每个任务一份**页目录**，但**页表是共享的**：内核的 identity map 在每个地址空间里都是同一份物理内存，所以换 CR3 不会把内核从自己脚下抽走 |
| `task.h` | 每任务 8 KiB 内核栈、栈底 canary、pid/状态/ticks/switches/parent | canary 是唯一能把"栈用超了"从静默踩内存变成一条 FAIL 的东西 |
| 命令 | `ps`（任务表）、`schedtest`（建两个任务、让定时器抢、回收） | `ps` 打印每个任务的 ticks 和被切入次数——"调度器在工作"是一个可读的数字 |

**验收**：11 条自检（任务 0 / pid / 页目录 / 栈与 canary / 退出码 / **中断标志跨切换存活** /
每个任务都被计过时 / 每个任务都被切入过 / 栈没被写穿 / 回收后堆回到起点 / TSS 和 CR3 指向正在
跑的那个任务）+ 8 条 QEMU 测试。最关键的一条是 `schedtest` 里那两个任务：它们**从不主动让出
CPU**，每个都要转够"定时器给自己记了 2 个 tick"才继续——所以"两个任务都跑到第二轮"这件事本身
就证明了抢占真的发生了。

## 设计要点

**每个加载器阶段都必须写 `org`，写成它真正执行的地址。** 不写 `org` 时 nasm 从文件开头
算绝对地址：加载在 0x700 的 stage2 会去线性 0x3xx 读字符串、写变量——也就是**中断向量表
里面**。向量表是可执行内存，所以唯一的症状是"引导诊断一个字都打不出来"，而引导看起来
完全正常。

**stage2 先用 1 个扇区的暂存区校验头部，再整体加载内核**，这样坏镜像不会先覆盖掉加载器
自己。

**内核把 INT 09h 留给固件，自己只用 INT 16h 取键。** 接管 INT 09h 的版本在真机语义下是
错的：读 0x60 会**吃掉**这次按键，于是 BIOS 的按键队列永远是空的，INT 16h 会永远阻塞；
改成链式调用 BIOS 处理程序更糟——`push seg:off` + `retf` 进去以后，BIOS 的 `iret` 会返回
到内核里被中断的那条指令，于是每按一个键内核都从头重启一次。

**内核在拥有自己的中断向量之前不开中断（IF 一直为 0）。** 内核没有安装任何向量，一旦
`sti`，第一个硬件中断就会从 IVT 的 0:0 跳出去，直接执行中断向量表和数据区。

**控制台原语 `console_putc` 不破坏任何通用寄存器。** 行编辑器在回显每个字符时把数据块
地址放在 EBX 里，而早期版本为了保存待写字符用了 BL——于是每敲一个键都会把"字符值"加到
那个指针上，`help` 变成 `unknown command: hl`。

**命令表里存的是相对表头的偏移**（`dw cmd_help - command_table`），因为 `dw cmd_help`
需要 16 位重定位。派发时必须加回**表头**，加错成"当前表项"只有第一项碰巧正确：`help`
正常，其它命令全都跳到各自处理函数内部几字节处。

**`.data` 里的字段偏移是手写常量，所以块的尺寸必须和偏移一致。** `SHELL_ARGS` 按 4 字节
对齐寻址，如果紧跟在长度字后面声明就会落在偏移 2——整个块错位两字节。现在每个块末尾都有
`%if ($ - block) != 期望大小 / %error` 的汇编期断言。

**控制台直接写显存**，引导后不再调用 BIOS。

## 踩坑记录（都已固化成测试）

每一个的症状都极具误导性，所以它们要么有测试，要么在测试里被显式提到：

- **字节寄存器编码**：`mod=3` 时 r/m 索引 4–7 是 AH/CH/DH/BH，不是 SP/BP/SI/DI。搞错会把
  值写进 SP，而 AH 永远是 0 —— 屏幕全空。
- **BDA 段基址**：`0040:0010` 的线性地址是 `0x410`，不是 `0x010`。
- **`jmp far` 有两种编码**：默认 16 位偏移，`0x66` 前缀才是 32 位偏移。nasm 的
  `jmp seg:label` 形式会从**输出文件开头**而不是 org 计算偏移。
- **`retf`/`iret` 必须先更新 CS 再设置 IP**：`set_ip()` 依赖当前的 CS 基址，顺序错了会让
  取指地址落在旧段里，表现为"跳到随机地址但 IP 看起来正常"。
- **视频单元是 `(属性<<8)|字符`**：顺序反了就是黑底黑字，看起来像"根本没画"。
- **写显存前不能让 `mov ax, 0xb800` 覆盖掉 AL 里的字符**；更一般地，**字符串打印函数
  不能悄悄破坏调用者的寄存器**（见 EBX 事故）。
- **字符串指针不能用 ESI**：ESI 是控制台状态基址，`console_putc` 会从 `[esi+0]` 读属性，
  改成字符串地址就会把消息里的字节当成属性。
- **不要把 ES 压在栈上跨中断**：BIOS 中断会把自己的帧压在被保存的值上面。所以 ES 由
  `console_init` 设置一次，之后是全局不变量。
- **COFF 重定位的符号索引是物理条目号**（含 aux 记录），不是逻辑符号号。
- **COFF 符号名有 inline 短名形式**（前 4 字节非零）；当成字符串表偏移就会把良构对象看成
  损坏文件。
- **group-1（0x80–0x83）的运算种类由 ModRM 的 reg 字段决定**，不是按 opcode 绑定。
- **缺少 `org` 的加载器阶段把数据写进了 IVT**：读回来的地址和写进去的一样，所以一切
  "照常工作"，只有打印和诊断全部失效。
- **字符串指令的字节形式永远按字节走**（A4/AA/AC/AE），`0x66` 前缀不改变它；只有
  A5/AB/AD/AF 跟随操作数大小。把 `lodsb` 当 16 位处理会让 SI 每次加 2，于是打印出来的是
  **隔一个字符**。
- **把低半字节存在 AH 里做十六进制打印是错的**：BIOS 电传输出需要 AH=0x0E，第一个数字
  就会把保存值冲掉，第二个数字永远打成 'E'。
- **模拟器给"没有处理程序的向量"送中断等于让 guest 跳进 IVT**：因此模拟器的 8042 在没有
  guest 处理程序时由固件路径自己确认这次按键。
- **中断关闭时的空闲检测要看 INT 16h 的队列，不是 8042 的锁存器**：否则每次输入后
  `run_until_idle` 都会一直跑到指令预算耗尽。
- **`type_text` 的大小写**：小写键位存在不代表大写不需要 Shift；早期实现把 `E` 当成 `e`
  发送，于是"忽略大小写"的测试其实从没送过大写字母。
- **freestanding i386 内核必须 `-mno-sse`**：目标默认开 SSE，gcc 会用
  `movdqu`/`movups` 拷贝数组；没设 `CR4.OSFXSR` 的内核执行第一条就 `#UD`，而且是三重
  故障，症状出现在**完全无关的代码**里。`compile_cpp` 现在带
  `-mno-sse -mno-sse2 -mno-mmx -mno-80387`，并有一条测试反汇编镜像找向量指令。
- **不要在 C++ 函数中间切栈**：入口桩必须在汇编里 `mov esp, ...` 然后 `call`。早期用一个
  C++ 可调用的 `load_esp()`——编译器认为帧和被调用者保存寄存器还在，于是横幅里的地址常量
  消失、结构体字段读错、字符串指针偏移、静态计数器被栈覆盖，而且**只在某些构建里出现**。
- **栈要放在 `.bss` 的最后一段**：栈向下增长，放在静态变量前面就会在普通函数调用里把它们
  覆盖掉。
- **`.bss` 的 `SizeOfRawData` 是"要保留的字节数"，不是文件内容**：按
  `PointerToRawData=0` 去切片会把 COFF 头拷进本该清零的 BSS——内核的静态计数器于是从
  `0x0005014C`（i386 机器类型 0x014C + 5 个 section）开始。
- **目标文件的 section 符号名会被截断到 8 字节**（`.bss.stack` → `.bss.sta`），按全名比较
  会漏判。
- **`extern "C"` 符号在这套工具链里带前导下划线**（`_kmain`），而 nasm 的 `global` 不带；
  查入口符号、解析重定位都必须接受两种拼法。
- **nasm 的 `%rep` 计数器不能和标签前缀同名**：`%assign irq 0` 之后写 `dd irq %+ index`，
  那个 `irq` 会被当成预处理器变量展开成数字。于是中断桩表里 16 个 IRQ 表项变成了裸的段内
  偏移、**没有重定位**，照样汇编、链接、启动——直到第一个中断跳进低内存。`build.py` 现在
  会读成品镜像里的桩表，任何一项不在镜像内就构建失败。
- **UART 的 IRQ 处理程序要循环抽干 FIFO**：开 FIFO 后一次中断可能代表好几个字节，只读一个
  会让剩下的字节等到下次中断才被取走——症状是"一整行里丢几个字符"。触发等级设成 1 字节。
- **QEMU 的 stdio 串口会丢突发数据**：`-serial stdio` 接管道时，一次 `write` 的多个字节
  只有第一个到达 guest。测试改用 `-serial tcp:...,server,nowait`；而且 QEMU 用 `-S` 暂停
  启动、等两个 socket 都连上再 `cont`，否则连接建立之前 guest 写的东西会被丢弃。
- **E820 的 entry size 是固件写的字节数，可能是 20**：如果按它当步长打包、kernel 端却按
  24 字节的结构体索引，读到的就是"0 条记录"的内存图。loader 现在把每条记录都规范化成
  24 字节（不足补零），步长固定。
- **`kprintf` 的 `%08x` 不是白给的**：没有宽度/补零支持时它会原样打印 `%08x`，而且不消费
  参数——后面所有 `%s`/`%x` 的参数就全错位了（表现为打印出 `(null)`）。后来补上了宽度，
  但补零的逻辑又错了一次：`console_put_hex32` **本来就固定打印 8 位**，而补零循环按"数值
  自己的位数"去补，于是 `%08x` 打 0x0885097F 会变成 9 个字符 `00885097F`——宿主算出来的
  是 8 位，看起来像校验和不匹配，其实数值是对的。现在只在宽度大于 8 时才补。
- **反汇编测试只能反汇编代码段**：反汇编器会把给它的任何字节解码成指令，所以扫整个镜像
  时也在"反汇编"字符串、数据表和全零的 `.bss`——文件系统长大之后，六个数据字节被解成
  `fld tword [edx+...]`，测试报了一个编译器从来没生成过的浮点指令。现在只把链接器给出
  的 code 段交给 `ndisasm`。
- **写进程的停机点要一致**：`reboot` 之前先 `sync`（把卷标记干净），否则每次正常重启都会
  让下次启动报"未干净卸载"——这种警告一旦变成常态就没人看它了。
- **`-boot c` 只挂软驱时会回落到软驱**：原来的"硬盘启动"测试一直跑在软驱路径上（`info`
  打印 `boot drive 0`），名字对了、覆盖面没有。把同一个镜像再以 `if=ide,index=0` 挂上并
  `-boot c` 之后，`info` 才会打印 `boot drive 128`——现在这条测试断言的就是这个数字。
- **空 IDE 通道有两种回答**：状态寄存器读到 `0x00`（总线浮空）或 `0xFF`（没有设备驱动）
  都表示"没有盘"，只判其中一个会让无盘机器在 `IDENTIFY` 上等满超时。
- **不同编译单元里同名的匿名命名空间变量会被链接器当成同一个对象**：`mbr.cpp` 与
  `fs.cpp` 都写了 `g_problem`，链接直接报 "defined more than once with different
  addresses"。内部符号按 mangled 名索引，名字必须自己保证唯一。
- **根 inode 的位图位忘了置 1，结果根目录把自己当成了文件**：`allocate_inode` 把 inode 1
  （根）重新分配出去，`docs` 目录里出现了指向自己的目录项，`ls` 于是无限循环。现在主机侧
  `check()` 有"每个已分配 inode 都必须能从根到达"这类检查，构建时就能报出来。
- **目录变短时不能把整块缩回去**：`dir_remove` 只把目录项清零、保留块，下一次创建复用这个
  空洞——否则一个长期使用的大目录会不停申请新块，而旧块永远漏着。
- **覆盖写要真的截断**：`write_file(..., truncate=True)` 会把写入末尾之后的块释放掉，
  否则"覆盖成更短的文件"会留下旧数据的块和旧的长度，读回来的是旧内容。
- **`ES:BX` 不能跨 64 KiB 边界，而 `ES = dest >> 4` 恰好会跨**：loader 原来用 `dest >> 4`
  拼段、低 4 位留给 BX，于是从 0x1F800 读 18 个扇区会写到 0x21C00，软驱的 DMA 通道直接回
  error 09h（"data boundary error"）。改成 **ES 对齐到 64 KiB 页、BX 是页内偏移**，分块
  上限也随之改成 `128 - low16(dest)/512`。这个 bug 一直存在，直到内核长大到超过 128 个
  扇区（第一次需要跨页读）才暴露——所以现在自检会打印**整份镜像的校验和**，宿主手里有
  "本该读到的字节"，一个字节错都藏不住。顺带：`read_chunk` 之后 ES 不再等于"目标的段"，
  所以 `check_header` 的 `ES:SI` 必须显式设置（否则它会去线性 0 读头部）。
- **不要拿"已加载的镜像"和"暂存的镜像"做全镜像比较**：加载后的 `.data` 是内核自己的运行
  状态（控制台颜色、卷缓存），全量比较会在一个合法变化的字节上失败。比较前 272 字节证明
  拷贝步骤，全量校验和交给宿主。
- **同一次 shell 会话里重复的等待标记会提前触发**：测试脚本用"等一个标记再发下一条"驱动
  串口，而 `wait_for` 是在**整个 transcript** 里找标记；两条命令都产生
  `cat: N bytes read` 时，第二个等待会立刻命中上一次的输出。每个标记必须唯一。
- **`--verbose` 链接器打印假设每个段都有 bounds**：丢弃段（`.debug*`、`.comment`）不占
  空间所以没有 bounds，查表直接 `KeyError: 'discard'`。现在丢弃段单独打印一行。
- **这套链接器按"段"对齐，不按符号对齐**：`__attribute__((aligned(4096)))` 的静态数组不会
  真的落在 4 KiB 边界上，因为段的位置由 `cofllink` 的 `SectionPlacement.align` 决定（`.bss`
  是 4）。所以页目录和页表**从 PMM 分配**（分配器只给页对齐的页），而不是放进 `.bss`——
  既拿到了对齐，也不必给链接器加"符号级对齐"这种新机制。
- **分页只能"先把正在执行的代码映射好，再开 PG"**：页目录、页表、内核镜像、显存、boot info
  全都得在 identity map 覆盖之内（页表本身也在其中，因为建表期间要写它们）。顺序反了就是
  开 PG 的下一条指令取指失败，而这个症状看起来像"分页代码本身写错了"。
- **内核映射一律不带 `PAGE_USER`**：这不是省事，而是"用户态看不到内核内存"的实现方式。
  等到有 ring3 时，只有用户地址空间的页才加 U/S 位。
- **在 guest 里跑第二次的检查必须幂等**：按需零页的检查第一次跑会映射一页，第二次再去
  "保留"同一段就发现页已映射、于是自己的保留失败、报告一个假的 FAIL。现在检查结束时把页
  解映射并归还，`paging_reserve_lazy()` 也允许重复保留同一区间（复用槽位，不叠加）。
- **`selftest` 会结束 guest**（它本来就是用退出码汇报结果的东西），所以"同一个会话里跑两次
  检查"需要另一个命令：`check` 打印同样的清单、带运行序号、然后留在 shell 里。运行序号不是
  装饰，它是测试用来做唯一标记的东西——"等一个标记再发下一条"的脚本不能重用重复的标记。
- **Python 的 `/` 不是 C++ 的 `/`**：`memmap.py` 解析头文件里的常量时，`(128 * 1024) / 4`
  在 Python 3 里得到 `32768.0`，一句 `isinstance(value, int)` 会把它静默丢掉，报告里就少一个
  常量。现在"IEEE 整数值的 float"会被转成 int。
- **页目录项也要 user 位**：两级页表都要允许，Ring 3 才能访问一页。只给页表项加 user 位时，
  程序会拿到一个 `present + user` 的缺页——错误码说"页在、而且是用户的、我只是读"，看起来
  像页本身有问题，其实是**目录项**拒绝的。这个错误码（0x05）是唯一能把它和"没映射"区分开
  的线索，也是这一轮最快定位的一个 bug。
- **进 ring 3 之前必须把数据段换成用户的**：`cs` 用 iret 换，`ds/es/fs/gs` 得自己 `mov`。
  带着内核的 DPL-0 选择子进用户态，程序第一条全局访问就缺页；而且它自己也没法 `mov` 那个
  选择子进来（CPL 3 加载 DPL 0 的段 = #GP）。
- **从 ring 3 回来的那条路带着 IF=0**：`return_to_kernel` 刚恢复内核栈，中间不能被 tick 打断，
  所以它 `cli` 之后 `ret` 回来。内核必须自己重新开中断——否则 shell 在 `hlt` 里等输入，
  表现是"程序跑完、提示符打出来、然后机器再也不理你"。
- **CPU 会改 GDT 里的 accessed 位**：自检比较描述符的 access 字节时必须把它掩掉，否则
  "boot 时通过、再跑一次就失败"——一个由 CPU 正常行为引起的假警报。
- **`esp0` 不能是 0，而且 `tss_init(kernel_stack_top)` 传的是符号的内容不是地址**：
  `kernel_stack_top` 是个标签，直接当参数传进去等于把栈顶设成那块内存里恰好存着的值（0）。
  另外用户程序退出后要把 esp0 还回启动时的栈，而不是清成 0——下一次 ring3 陷阱会把帧压到
  地址 0。
- **同一个目录下两个同名的源文件会共用一个 .o**：`kernel32/user.asm` 和 `kernel32/user.cpp`
  都编译成 `build/user32.o`，于是同一个对象被链接了两次、落在两个不同的地址上，报出来的是
  "这个 static 函数定义在多个地址"——指向函数而不是文件名。现在 `build.py` 在链接前直接检查
  对象名唯一并给出人话错误（这个文件也因此改名为 `ring3.asm`）。
- **切换任务必须关中断，而且 IF 要跟着上下文走**：这是这一阶段最难查的一个。`schedule()` 从
  任务代码里被调用时 IF=1，于是定时器可以正好落在"旧任务已经不是 Running"和"新任务的栈已经
  装上"之间——中断处理函数看到的是一个和 CPU 实际所在位置不一致的任务表，而它**有权再切一次**
  换。后果是同一个 `esp` 被存进两个任务的字段里：两个任务都以为自己在跑，其中一个恢复时执行的是
  别人的栈、别人的代码。症状各不相同（tick 记到错误的任务上、某个任务永远不动、几十毫秒后
  "没有可运行任务"），但根因只有一个。修法是两件事一起做：`sched_switch_to()` 一进来就 `cli`，
  并且在 `switch_to` 里把 **EFLAGS 和寄存器一起压栈**——否则从 `sched_yield()` 里被换出去的任务
  回来时 IF 还是 0，从此再也不被抢占（"某个任务一旦让过一次 CPU 就霸占机器"）。自检里专门有
  一条"中断标志跨切换存活"，就是为了让这个 bug 只能以 FAIL 的形式出现。
- **EOI 必须在处理函数*之前*发给 PIC**：8259 在"服务中"寄存器被清掉之前不会再送同一条线的
  中断，而定时器的处理函数**会切换任务**——切换意味着这个处理函数挂起在某条栈上，等那个任务
  下次被调度才继续。EOI 放在处理函数后面就等于"几十毫秒以后才确认"，症状是：定时器跳一下、
  调度器切一次、**然后时钟彻底停住**，看起来像"某个任务永远不会被抢占"。进中断门时 IF 已被
  清掉，所以先 EOI 不会被同一条线重入。
- **不能把"可以跑了"和"栈还没填完"合并成一个状态**：`Task` 结构体是一边填一边变的，而定时器
  不等谁。早期版本在 `esp` 赋值**之前**就把状态写成 `Ready`，于是 tick 正好落在中间时会切到一个
  `esp = 0` 的任务——报出来的是几千行之外的一条通用保护错（`iret` 上），和真正的原因毫无关系。
  现在有独立的 `New` 状态，只有 `sched_add()` 能把它变成 `Ready`（而且那个赋值本身不会被
  "切到一半"）。
- **切换任务时必须告诉任务层"现在是哪个任务"**：`switch_to` 只换栈和寄存器，`task_current()`
  读的是另一份变量。忘了同步它，新任务第一次跑 `task_trampoline` 时查到的是**它替换掉的那个
  任务**，于是拿别人的入口函数、最后以别人的身份退出。症状是"没有任何输出地卡住"——最难查的
  一种调度器 bug。
- **新任务的 IF 是自己负责开的**：`ret` 不恢复 EFLAGS，所以从定时器（中断门，IF=0）切进来的
  新任务会继承 IF=0，然后**永远不会被抢占**。现在造出来的栈帧里有一个 EFLAGS 字（`0x202`），
  `switch_to` 用 `popfd` 装进 CPU，`task_trampoline` 里的 `sti` 只是保险——两处都写了注释，
  因为这是那种"看起来调度器坏了、其实是标志位"的问题。
- **回收栈（`kfree`）只能在任务上下文里做**：中断里做堆操作，可能正好撞在别人被抢占的
  `kmalloc` 中间——那半截空闲链表会让两次分配拿到同一块内存。所以 `task_reap()` 由
  `task_join()`/自检这类任务上下文调用，**调度器绝不回收**。
- **测试自己也会有竞态**：演示任务"这一轮要跑够 2 个 tick"的目标值原本是在放开抢占**之后**
  读的，于是如果它在这中间被切走又切回来，基准值已经变了，一轮就变成 4 个 tick。现在基准值和
  打印在同一个 `sched_pause()` 区间里取——这也顺带说明 `sched_pause()` 存在的意义（控制台一行
  不能被另一个任务的输出打断）。
- **每个 `for(;;) schedule()` 都要有出路**：`task_exit()` 的最后一步是"切走，永远不回来"，
  但如果调度器一个可运行任务都找不到，它就会**无限空转、一个字都不打**。现在这个循环在
  `schedule()` 返回后检查"还是我自己吗"，是的话 `panic("no runnable task: ...")`——按这个项目
  的老规矩：**报告先于停机**，卡死也要卡出个说法。
- **两套错误码区间重叠就等于一套**：文件系统用 -1..-16，第一版的 syscall 错误码也落在那一带
  （`E_FAULT` 和 `FS_BAD_FD` 都是 -14），于是"哪里错了"的翻译函数只能有一个意思。现在
  syscall 错误码占 -32..-39，`sys_error_text()` 两套都认。
- **汇编桩点名调用的 C++ 函数必须是 `extern "C"`**：`int 0x80` 的桩写 `call syscall_dispatch`，
  而没有 `extern "C"` 的定义会被 mangle，链接时报"未解析符号"，名字长得像 C++ 而不是像
  函数名。
- **"永不重建"的承诺需要一个"合并"操作来配对**：数据盘不被构建覆盖，所以旧构建做出来的盘
  上不会有后来才加入产物的东西（比如 `/bin` 里的 ring 3 程序），用户看到的是
  `run /bin/hello: no such file or directory`——一个完全正确、但没有任何线索的答案。补上的是
  `build.py data-disk --update`（以及 `myfs.py --put`）：**只**按名字创建/替换构建拥有的文件，
  其余一律不动。教训不是"数据盘该被重建"，而是"一个只增不减的保证，必须同时给出一条把它
  变新的路"；另外 `run.py` 在挂载前会检查 `/bin` 并提示，把答案放在问题被问的地方。

## 下一步

路线图第一阶段的 **1a（分页/物理分配器/内核堆/缺页）和 1b（ring3/TSS/syscall/usercopy/用户镜像）
都已完成**，第二阶段的 **2a（任务与抢占式轮转调度）也已完成**：`vm` 打印真实的页表与堆数字，
`ps` 打印任务表，`run /bin/hello` 真的在 ring 3 跑完并回到 shell，68 项自检分四组
（内存 / 特权级 / 文件系统 / 调度）盯着它们，`check` 可以在不退出的情况下重跑。

**下一步是 2b：让用户程序成为真正的任务。** 顺序是：给 `Task` 加用户半区（用户页表 + 用户栈），
把 `exec_user()` 从"代替调用者同步跑"改成"建立一个任务"，然后才是 `fork` 的写时复制
（页表项只读共享 + 页帧引用计数）、`exit`/`wait` 的父子关系、以及信号（Ctrl-C → SIGINT）。
这一步落地之后，`sched_pause()` 在 `exec_user()` 里的那段特殊照顾就可以删掉了——它存在只是
因为"用户程序不是任务"，而不是因为抢占本身有错。再往后是管道/共享内存与最小 tty（行规程），
那两张是 2c。

完整计划（含每阶段的交付物、验收断言、非目标与风险）见
**[`docs/roadmap.md`](roadmap.md)**。另外两件不在主线上但值得做的：把保护模式补进自研模拟器
（让 32 位也能在无 QEMU 的机器上验收），以及文件系统的追加写与更大文件（双间接块）。
